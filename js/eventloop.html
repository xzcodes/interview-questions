异步与事件循环（Asynchronous & Event Loop） ​

1. 概念定义 ​

  • 异步：指任务执行不阻塞主线程，任务完成后通过回调、Promise 或 async/await 机制通知结果。
  • 事件循环：JavaScript 的机制，用于调度异步任务，确保它们在主线程空闲时按顺序执行。

2. 产生原因 / 工作原理 ​

  • 产生原因：JavaScript 是单线程，为避免阻塞 UI 渲染或 I/O 操作，引入异步机制。
  • 工作原理：
    • 主线程执行同步任务；
    • 异步任务（如 setTimeout、Promise、I/O）被放入任务队列；
    • 事件循环不断检查任务队列，执行已准备好的异步任务；
    • 微任务（microtask）优先于宏任务（macrotask）执行，如 Promise.then、queueMicrotask；
    • 宏任务（macrotask）包括 setTimeout、setInterval、I/O 回调等。

3. 典型示例 ​

console.log('Start');

setTimeout(() => {
  console.log('Timeout');
}, 0);

Promise.resolve().then(() => {
  console.log('Promise');
});

console.log('End');
  • 解释：
    • 输出顺序为：Start → End → Promise → Timeout
    • 因为 Promise.then 是微任务，setTimeout 是宏任务，事件循环先执行微任务队列，再执行宏任务。

4. 应用场景 ​

  • 异步 I/O 操作：如网络请求、文件读取，避免阻塞主线程。
  • 用户交互：处理点击事件或动画渲染，保证流畅 UI。
  • 定时任务：如轮询或延迟执行操作。
  • 前端数据流管理：结合 Promise、async/await 编写可读性高的异步逻辑。

5. 常见考点与陷阱 ​

  • 微任务 vs 宏任务：理解微任务总是在当前轮事件循环结束前执行。
  • setTimeout(…, 0) 并非立即执行：即便延迟 0，也会进入宏任务队列等待执行。
  • 异步堆栈与调试难度：异步回调可能导致调试复杂，出现回调地狱。
  • 阻塞主线程：大量同步任务会阻塞异步任务执行，影响性能。

6. 优缺点总结 ​

  • 优点：
    • 避免阻塞主线程，提高并发能力；
    • 支持非阻塞 I/O，提高程序性能；
    • 与 UI 渲染协同，提升用户体验。
  • 缺点：
    • 异步代码逻辑复杂，容易出错；
    • 微任务与宏任务顺序不熟悉易造成理解错误；
    • 调试和错误追踪困难。

7. 一句话总结 ​

  • 异步与事件循环是 JavaScript 单线程高效运行的核心机制，通过任务队列和事件循环保证异步任务按正确顺序执行。

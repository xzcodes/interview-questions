# 垃圾回收（Garbage Collection）

## 1. 概念定义

- **垃圾回收**：JavaScript 自动管理内存的机制，通过回收不再使用的对象，释放内存空间，避免内存泄漏。

## 2. 产生原因 / 工作原理

- **产生原因**：开发者手动管理内存容易出错，容易造成内存泄漏。垃圾回收机制自动管理对象的生命周期。
- **工作原理**：
    - **标记清除（Mark-and-Sweep）**：从根对象（如全局对象）开始，标记所有可达对象，未被标记的对象则被回收。
    - **引用计数（Reference Counting）**：每个对象维护引用计数，当计数为 0 时对象可被回收。
- **浏览器实现**：现代 JavaScript 引擎主要采用标记清除法，结合增量和分代回收策略优化性能。

## 3. 典型示例

```
let obj = { name: 'Alice' };
obj = null;  // obj 对象失去引用，可以被垃圾回收
```

- **解释**：`obj` 对象被赋值为 `null` 后，不再有任何引用指向它，垃圾回收机制会自动回收其占用的内存。

## 4. 应用场景

- **大型应用内存管理**：确保不再使用的对象及时释放，防止内存泄漏。
- **闭包和定时器**：清理不再需要的闭包或定时器引用，避免内存占用持续增长。
- **浏览器和 Node.js**：JavaScript 运行环境中保证程序长时间运行不会耗尽内存。

## 5. 常见考点与陷阱

- **内存泄漏常见原因**：
    - 全局变量长期存在
    - 闭包引用未清理
    - 未清理的定时器、事件监听器
- **循环引用问题**：引用计数机制无法处理循环引用，需要标记清除来解决。
- **不确定性**：垃圾回收执行时间不可预测，可能影响性能。

## 6. 优缺点总结

- **优点**：
    - 自动管理内存，减少开发者负担；
    - 降低内存泄漏风险；
    - 提高程序安全性和稳定性。
- **缺点**：
    - 垃圾回收时间不可控，可能造成短暂性能波动；
    - 需要理解闭包和引用，避免间接造成内存泄漏。

## 7. 一句话总结

- JavaScript 的垃圾回收机制通过标记清除和引用计数自动管理内存，帮助开发者减少内存泄漏风险。
